標準化をいつするかで、手間が桁で変わる

例：100項目のテンプレートで、1,000症例の電子カルテのデータを集めた場合

テンプレートを作る段階で標準化

項目1つにつき1回の判断で済む

値は辞書から選ぶ形にし、自由記載をなくす。そのまま解析に使える

100回

項目を標準化せず、辞書も使わない

100項目 × 1,000症例 ＝ 10万個のデータを、1つずつ検証する

データが溜まるほど、手間は増える

10万回

後から完全に標準化することは、できない
（0:25）標準化の判断をいつするかで、最終的な手間が大きく変わります。 100項目のテンプレートで、1,000症例の電子カルテのデータを集めたとします。 テンプレートを作る段階で標準化すれば、判断はテンプレートの項目1つにつき1回なので、100回で済みます。値も、辞書から選ぶ形にして自由記載をなくせば、そのまま解析に使えます。 項目を標準化せず、辞書も使わなかったらどうなるか。100項目かける1,000症例で、10万個のデータを1つずつ検証することになります。100回に対して10万回です。しかもデータが溜まるほど、手間は増えていきます。 そして、こうした作業をしたことのある方なら誰もが感じているように、後から完全に標準化することはできません。

世界標準：CDISC・OMOP・FHIRの役割分担

JASPEHR は、FHIR のテンプレートを器にして、世界標準の変数と用語を載せる

CDISC（SDTM・ADaM）OMOP CDMHL7 FHIR

J. Abolafia "Future Clinical Data Submission Standards: CDISC, FHIR, OMOP, or Hybrid Model" をもとに作成

（1:50）ここで、3つの標準の関係を整理しておきます。 CDISC は、治験の結果を規制当局に提出するための標準で、FDA と PMDA が承認申請で求めています。データは、変数名と値の決まった表の形です。 OMOP は、観察研究やリアルワールドデータの解析で広く使われている標準で、こちらも表の形です。 FHIR は、診療情報をやり取りするための標準で、JSON などの文書の形をとります。 どれが優れているかではなく、役割の分担です。今回の仕組みでは、FHIR のテンプレートを器にして、そこに CDISC の変数と用語を載せ、同じ形で OMOP の置き場所も持たせています。

FHIR の4つのリソース

帳票の「ひな形」「選択肢」「辞書」と「記入済みの1枚」

Questionnaire

帳票のひな形。項目・入力の型・表示名・選べる答え

何を聞くか

選択肢を指す➜

ValueSet

ある項目で選べる答えの一覧

プルダウンの中身

辞書を指す➜

CodeSystem

用語の辞書そのもの。コードと表示名

例：MedDRA、LOINC

QuestionnaireResponse

記入済みの帳票1枚。項目ごとの答え

何と答えたか

⬆ どのひな形の、どの版に答えたかを持つ

⬈ 選んだ答えは「どの辞書の、どのコードか」の組で残る

ひな形・選択肢・辞書の3つで「何を聞くか」が決まり、記入済みの1枚が「答え」を持つ
（4:05）ここで、FHIR で帳票を表す4つの部品を簡単に紹介します。 1つ目の Questionnaire は、帳票のひな形です。どんな項目があり、どんな型で入力し、どんな答えを選べるかを決めます。 2つ目の ValueSet は、ある項目で選べる答えの一覧、つまりプルダウンの中身です。 3つ目の CodeSystem は、用語の辞書そのもので、コードと表示名を持ちます。MedDRA や LOINC も、この形で持つことができます。 4つ目の QuestionnaireResponse は、記入済みの帳票1枚です。どのひな形のどの版に答えたかと、項目ごとの答えを持ちます。選んだ答えは、どの辞書のどのコードか、という組で残ります。 ひな形と選択肢と辞書の3つで「何を聞くか」が決まり、記入済みの1枚が「答え」を持つ、という関係です。

組み込んだ4つのメタデータ

目標：カルテへの入力が、そのまま CDISC に準拠する

メタデータ規模FHIR での持たせ方状態
変数1. SDTM の変数名63種類・1,523変数各項目の extension✓ JSON のサンプルを提供
用語2. 統制用語（CT）1,181種類・44,830語CodeSystem ＋ ValueSet✓ 1,181の CodeSystem を読み込み
3. MedDRA1種類・90,471語CodeSystem✓ JSON のサンプルを提供
4. IDF・WHODrug

WHODrug は任意。ライセンスの無い施設は IDF で止める

1種類・19,415語CodeSystem（IDF）✓ JSON のサンプルを提供
（5:35）組み込んだメタデータは4つです。1つ目と、2つ目から4つ目とでは、役割の段が違います。 1つ目は SDTM 変数で、その項目が何の変数かを表し、各項目の extension に持たせます。2つ目から4つ目は、答えに使う用語の辞書です。2つ目は CT で、1,181のコードリストを CodeSystem として読み込みました。3つ目は MedDRA、4つ目は IDF 経由の WHODrug です。 WHODrug は、日本語の医薬品マスターである IDF で入力し、対応表で WHODrug に変わります。WHODrug のライセンスが無い施設は、IDF までで止めることができます。 用語のサンプルは、参加ベンダーに JSON で渡してあります。
